# ⚙️ ميزة الإعدادات (Settings Feature)

تمت إعادة هيكلة ميزة الإعدادات بالكامل لتتبع معمارية نظيفة وخالية من تسريبات منصة التشغيل (Platform Leakage) والارتباطات المتداخلة مع الميزات الأخرى.

## 📂 الهيكل الدليلي (Directory Structure)

```
lib/features/settings/
│
├── di/                      # حقن الاعتماديات الخاص بميزة الإعدادات
│
├── presentation/            # طبقة العرض وإدارة الحالة
│   ├── cubit/               # منطق العمل وعزل فحص المنصة (SettingsCubit)
│   └── views/               # واجهة المستخدم النقية (SettingsView)
│
└── settings.dart            # ملف التصدير البرميلي (Barrel File) للميزة
```

## 🛠️ القرارات المعمارية والتقنية (Architectural & Technical Decisions)

### 1. إزالة تسريب المنصة (Eliminating Platform Leakage)
* سابقاً، كانت واجهة المستخدم (`SettingsView`) تحتوي على فحوصات مباشرة لمنصة التشغيل عبر استخدام `kIsWeb` لتعديل المظهر أو سلوك المشاركة والتقييم.
* تم حل المشكلة بنسبة 100% عبر إزاحة هذا المنطق إلى إدارة الحالة بإنشاء `SettingsCubit` و `SettingsState`؛ حيث يقوم الكيوبيت بحساب وحقن القيم مسبقاً:
  * `isRatingSupported`: يُعلم الواجهة ما إذا كان التقييم مدعوماً في البيئة الحالية أم لا.
  * `shareText`: يُحدد النص المخصص للمشاركة بناءً على بيئة تشغيل التطبيق (ويب أو تطبيق هاتف).
* أصبحت الواجهة نقية بالكامل وتعتمد فقط على البيانات القادمة من الحالة، مما يسهل اختبارها وتعديل سلوكها بشكل مستقل.

### 2. فك الارتباط المعماري (Decoupling)
* تم نقل نافذة التحقق من الرمز السري للمطورين `SecretPinDialog` بالكامل من ميزة الواجهة الرئيسية (`home`) إلى المجلد المشترك للنواة `lib/core/common/widgets/` نظراً لكونها تُستدعى وتُستخدم من شاشة الإعدادات وكتأمين لواجهة المطورين، وبذلك تم فك الارتباط تماماً بين ميزتي `home` و `settings`.

### 3. تصدير برميلي نظيف (Barrel Export)
* تم توفير ملف تصدير موحد `settings.dart` لتصدير العناصر الأساسية للميزة بشكل نظيف ومنع استيراد الملفات الداخلية العميقة بشكل عشوائي من قِبل الميزات الأخرى في المشروع.
