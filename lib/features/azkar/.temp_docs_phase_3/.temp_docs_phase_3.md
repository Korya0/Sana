        # F01 — Requirements

        ## Feature: Azkar Reminder Notifications

        🎯 **Objective**


        فهم المشكلة والـ Business Rules قبل كتابة أي Code.


        ---

        # 1) Goal

        ## المشكلة

        المستخدم يقرأ الأذكار داخل التطبيق، لكن قد ينسى الرجوع إليها في الأوقات المناسبة.

        ## الحل

        إضافة نظام تذكيرات يسمح للمستخدم بإنشاء Reminder مرتبط بكل ذكر، بحيث يحصل على Notification في الوقت الذي يحدده، وتوجيهه مباشرة إلى الذكر المطلوب.

        ## الهدف الأساسي:

        مساعدة المستخدم على تذكر الأذكار في وقتها المحدد.


        ## أهداف إضافية:

        - زيادة انتظام المستخدم في قراءة الأذكار.
        - تسهيل بناء عادة يومية مرتبطة بالأذكار.

        ---

        # 2) User Story

        ## Primary User Story

        ```
        As a user,
        I want to set reminders for my azkar,
        so that I don't forget to read them at the preferred time.
        ```

        ---

        ## User Scenarios

        ### Scenario 1 — Create Reminder

        ```
        Given:
        User opens a specific Azkar page

        When:
        User creates a reminder and selects time

        Then:
        The app schedules a local notification
        for that Azkar.
        ```

        ---

        ### Scenario 2 — Receive Notification

        ```
        Given:
        User has an active reminder

        When:
        The scheduled time arrives

        Then:
        The user receives a notification.
        ```

        ---

        ### Scenario 3 — Open Azkar From Notification

        ```
        Given:
        Notification appears

        When:
        User taps notification

        Then:
        The app opens the related Azkar page.
        ```

        ---

        # 3) Business Rules

        ## Reminder Ownership

        - كل Reminder مرتبط بذكر محدد.

        Example:

        ```
        Morning Azkar
        |
        |
        Reminder
        08:00 AM
        ```

        لا يوجد Reminder عام لكل الأذكار.

        ---

        ## Multiple Reminders

        يسمح للمستخدم بإنشاء أكثر من Reminder لنفس الذكر.

        Example:

        ```
        Morning Azkar

        Reminder 1:
        08:00 AM

        Reminder 2:
        12:00 PM
        ```

        ---

        ## Reminder State

        كل Reminder له حالة:

        ```
        Enabled
        Disabled
        ```

        Disable:

        - لا يحذف Reminder.
        - فقط يوقف Schedule.

        ---

        ## Repeat Rules

        يدعم:

        ### Daily

        ```
        Every day at 08:00
        ```

        ### Custom Days

        Example:

        ```
        Saturday
        Sunday
        Monday
        ```

        ---

        ## Permission Rule

        لا يتم طلب Notification Permission عند فتح التطبيق.

        الـ Flow:

        ```
        User creates first reminder

        ↓

        Explain why permission is needed

        ↓

        Request permission

        ↓

        Schedule notification
        ```

        ---

        ## Local Only Rule

        كل البيانات محلية.

        لا يوجد:

        - Account
        - Backend
        - Cloud Sync
        - Firebase Notification

        ---

        ## Timezone Rule

        Reminder يعتمد على:

        ```
        Local Timezone
        ```

        ويتم حفظ الـ timezone مع الـ reminder.

        Example:

        ```
        08:00 AM
        Africa/Cairo
        ```

        ---

        ## Device Time Change Rule

        عند حدوث تغيير في وقت الجهاز:

        يتم:

        ```
        Detect Change

        ↓

        Recalculate Active Reminders

        ↓

        Reschedule Notifications
        ```

        ---

        # 4) Functional Requirements

        ## Reminder Creation

        النظام يجب أن يسمح للمستخدم:

        - إنشاء Reminder لذكر معين.
        - اختيار الوقت.
        - اختيار نوع التكرار.
        - حفظ Reminder.

        ---

        ## Reminder Management

        النظام يجب أن يسمح:

        - تعديل Reminder.
        - حذف Reminder.
        - تشغيل Reminder.
        - إيقاف Reminder.

        ---

        ## Notification Scheduling

        النظام يجب أن:

        - يستخدم Local Notifications.
        - يعمل بدون Internet.
        - يعمل بدون Backend.
        - يدعم التطبيق المغلق.

        ---

        ## Notification Content

        النظام يجب أن يعرض:

        - عنوان Notification.
        - رسالة من Templates جاهزة.

        Example:

        ```
        حان وقت أذكار الصباح
        ```

        ---

        ## Notification Navigation

        عند الضغط:

        يجب فتح:

        ```
        Specific Azkar Screen
        ```

        باستخدام:

        ```
        azkarId
        ```

        داخل Notification Payload.

        ---

        # 5) Non Functional Requirements

        ## Reliability

        - لا يجب فقدان Reminder بعد إعادة تشغيل التطبيق.
        - يجب إعادة جدولة التذكيرات عند الحاجة.

        ---

        ## Performance

        - عدد كبير من Reminders لا يؤثر على أداء التطبيق.
        - Scheduling يجب أن يكون Lightweight.

        ---

        ## Maintainability

        يجب فصل:

        ```
        Reminder Logic

        عن

        UI
        ```

        باستخدام:

        - Repository
        - UseCase
        - Scheduler Service

        ---

        ## Offline Support

        Feature يجب أن تعمل بدون:

        - Internet
        - API
        - Authentication

        ---

        ## User Experience

        - Permission explanation واضح.
        - إنشاء Reminder يكون بسيط.
        - الوصول للذكر من Notification يكون مباشر.

        ---

        # 6) Edge Cases

        ## Permission Denied

        Scenario:

        ```
        User creates Reminder

        ↓

        Permission denied
        ```

        Expected:

        ```
        Show message:
        Enable notifications from settings
        ```

        ---

        ## Empty Reminder

        User يفتح Reminder Settings ولا يحفظ.

        Expected:

        ```
        No Reminder created
        ```

        ---

        ## Delete Azkar

        إذا حذف ذكر:

        ```
        Azkar deleted

        ↓

        Related reminders deleted
        ```

        ---

        ## Disable Reminder

        Expected:

        ```
        Reminder remains saved

        Notification stops
        ```

        ---

        ## Device Restart

        Expected:

        ```
        App restores active reminders
        ```

        ---

        ## Timezone Change

        Expected:

        ```
        Recalculate reminder schedule
        ```

        ---

        ## Duplicate Reminder

        User creates:

        ```
        08:00 AM
        ```

        مرة أخرى.

        Decision:

        يسمح، لأن المستخدم قد يريد أكثر من Reminder.

        ---

        # 7) Acceptance Criteria

        ## Reminder Creation

        - [ ]  User can create reminder from Azkar page.
        - [ ]  Reminder is linked to specific Azkar.
        - [ ]  User can select time.
        - [ ]  User can select repeat option.

        ---

        ## Reminder Management

        - [ ]  User can edit reminder.
        - [ ]  User can delete reminder.
        - [ ]  User can enable/disable reminder.

        ---

        ## Notification

        - [ ]  Notification appears at scheduled time.
        - [ ]  Notification works offline.
        - [ ]  Default sound is used.
        - [ ]  Notification opens correct Azkar page.

        ---

        ## Permission

        - [ ]  Permission requested only when needed.
        - [ ]  User understands why permission is required.

        ---

        ## Persistence

        - [ ]  Reminders survive app restart.
        - [ ]  Active reminders are restored.

        # F02 — Product Spec (PRD)

        ## Feature: Azkar Reminder Notifications

        🎯 **Objective**


        تحويل الـ Feature من مجرد فكرة إلى Product Specification واضحة يمكن الرجوع لها أثناء التنفيذ.


        ---

        # 1) Overview

        ## Feature Description

        نظام Reminder داخل تطبيق الأذكار يسمح للمستخدم بإنشاء تذكيرات محلية مرتبطة بكل ذكر، بحيث يتم إرسال Notification في الوقت المحدد، وعند الضغط عليها يتم فتح صفحة الذكر مباشرة.

        ---

        ## Problem Statement

        المستخدم قد يقرأ الأذكار داخل التطبيق، لكنه قد ينسى العودة إليها في الأوقات المناسبة.

        الحل هو توفير وسيلة تذكير بسيطة ومرنة تساعده على الالتزام بقراءة الأذكار.

        ---

        ## Scope

        ### Included:

        ✅ Create Reminder لكل ذكر

        ✅ Multiple Reminders لكل ذكر

        ✅ Edit Reminder

        ✅ Delete Reminder

        ✅ Enable / Disable Reminder

        ✅ Daily Repeat

        ✅ Custom Days Repeat

        ✅ Local Notifications

        ✅ Open Specific Azkar Screen

        ✅ Local Persistence

        ✅ Permission Handling

        ✅ Timezone Handling

        ---

        ### Not Included:

        ❌ Backend

        ❌ Firebase Cloud Messaging

        ❌ Account Sync

        ❌ Smart Suggestions

        ❌ AI Reminders

        ❌ Habit Tracking

        ---

        # 2) Functional Requirements

        ---

        # Reminder Creation

        ## Description

        المستخدم يستطيع إنشاء Reminder من صفحة الذكر.

        Flow:

        ```
        Azkar Details Screen

        ↓

        Reminder Section

        ↓

        Create Reminder

        ↓

        Select Time

        ↓

        Select Repeat

        ↓

        Save

        ↓

        Schedule Notification
        ```

        ---

        ## Requirements

        The system should:

        - Allow user to choose reminder time.
        - Allow user to choose repeat pattern.
        - Link reminder with specific Azkar.
        - Save reminder locally.
        - Schedule notification.

        ---

        # Reminder Management

        ## Edit Reminder

        User can modify:

        - Time.
        - Repeat pattern.
        - Active status.

        Example:

        ```
        Morning Azkar Reminder

        Old:
        08:00 AM

        New:
        09:00 AM
        ```

        System should:

        ```
        Cancel Old Schedule

        ↓

        Create New Schedule
        ```

        ---

        ## Delete Reminder

        When user deletes:

        ```
        Reminder

        ↓

        Remove Local Data

        ↓

        Cancel Notification
        ```

        ---

        ## Enable / Disable

        Example:

        ```
        Morning Azkar

        Reminder:

        ON  ✅

        OFF ❌
        ```

        When disabled:

        - Keep data.
        - Cancel scheduled notification.

        When enabled:

        - Schedule again.

        ---

        # Notification System

        ## Notification Creation

        The system uses:

        ```
        flutter_local_notifications

        +

        Local Scheduler
        ```

        ---

        ## Notification Content

        Templates:

        Example:

        ```
        Title:
        حان وقت الذكر

        Body:
        لا تنس أذكار الصباح
        ```

        User cannot customize text in MVP.

        ---

        ## Notification Action

        When user taps:

        ```
        Notification

        ↓

        Open App

        ↓

        Read Payload

        ↓

        Navigate

        ↓

        Azkar Details Screen
        ```

        # 4) Error States

        ---

        ## Notification Permission Denied

        Scenario:

        ```
        User creates reminder

        ↓

        Permission denied
        ```

        Result:

        Display:

        ```
        Notifications are disabled.
        Please enable them from settings.
        ```

        ---

        ## Scheduling Failed

        Scenario:

        ```
        Create Reminder

        ↓

        Notification scheduling fails
        ```

        Result:

        - Show error message.
        - Do not save invalid state.

        ---

        ## Invalid Time

        Scenario:

        User selects invalid time.

        Result:

        ```
        Show validation error
        ```

        ---

        ## Storage Failure

        Scenario:

        Cannot save reminder.

        Result:

        ```
        Show retry option
        ```

        ---

        ## Missing Azkar Data

        Scenario:

        Notification contains invalid azkarId.

        Result:

        ```
        Open Azkar Home Screen
        ```

        ## Creation

        - [ ]  Reminder is connected to correct Azkar.
        - [ ]  Notification is scheduled.
        - [ ]  Data survives app restart.

        ---

        ## Management

        - [ ]  User can edit reminder.
        - [ ]  User can delete reminder.
        - [ ]  User can disable reminder.
        - [ ]  Disabled reminder does not trigger notifications.

        ---

        ## Notification

        - [ ]  Notification appears at correct time.
        - [ ]  Works without internet.

        - [ ]  Permission is requested at the correct moment.
        - [ ]  User sees explanation before permission request.

        ---

        ## Time Handling

        - [ ]  Reminder respects device timezone.
        - [ ]  Reminder can recover after timezone/device time changes.

            # Task 5 — Notification Scheduling Failure

            Scenario:

            Hive save نجح ولكن Scheduling فشل.

            المشكلة:

            لدينا Data بدون Notification.

            ---

            Decision:

            نستخدم Transaction-like flow:

            ```
            Schedule Notification

                    ↓

            Save Hive
            ```

            أو لو النظام الحالي:

            ```
            Save

            ↓

            Schedule Failed

            ↓

            Rollback
            ```

            ---

            الهدف:

            عدم وجود Reminder فعال بدون Notification.
