# 🛠️ Developer Dashboard (لوحة المطورين)

لوحة تحكم خفيفة (Admin Panel) داخل التطبيق مخصصة لمطوري وإداريي تطبيق **سنا (Sana)**. تهدف هذه الميزة إلى عرض وإدارة آراء وتعليقات المستخدمين (Feedback) المرسلة من التطبيق، مع إمكانيات للنسخ، المشاركة كصورة، وحذف التعليقات.

---

## 🏗️ البنية المعمارية (Architecture)
تمت كتابة هذه الميزة بدقة متناهية لتعمل وفقاً لقواعد البنية النظيفة (Clean Architecture) الخاصة بالمشروع والمحددة في ملف `.agent`. وتتكون من الطبقات التالية:

### 1. طبقة الـ Domain
- **`FeedbackEntity`:** الكيان الأساسي للتعليقات. كائن بحت (Pure Object) مستقل تماماً عن تفاصيل قاعدة البيانات ومكتبات خارجية (لا يعتمد على Firebase ولا على Equatable)، ومزود بدوال المقارنة اليدوية `==` و `hashCode` لضمان الأداء الأفضل في الـ UI.

### 2. طبقة الـ Data
- **`DashboardFeedbackModel`:** يمتد من `FeedbackEntity` ومسؤول عن عملية الـ Serialization (تحويل بيانات Firebase JSON إلى كائنات). يتميز بأنه آمن من أخطاء الـ `TypeError` حيث يتعامل بذكاء مع التحويلات المعقدة كـ `Map<String, dynamic>`.
- **`INoSqlDatabaseClient` / `DashboardRemoteDataSource`:** تم فصل `FirebaseFirestore` خلف واجهة تجريدية لضمان عدم ارتباط الميزة بشكل صلب بقاعدة البيانات، مما يسهل عملية الاختبار والتوسعة في المستقبل.
- **`DashboardRepoImpl`:** 
  - يعمل كمدير وحيد للبيانات (Single Source of Truth).
  - يحتفظ بنسخة (Cache) محلية من التعليقات في الذاكرة.
  - يدعم الحذف السريع والوهمي (Optimistic Delete) لتجربة مستخدم لحظية.
  - في حال الفشل في الشبكة، يقوم بالاعتراض (Catch `Object`) لتجنب أي إغلاق مفاجئ (Crash) وإعادة بناء السجل بشكل صحيح وإرسال الأخطاء التقنية المجهولة تلقائياً إلى Firebase عبر `AppLogger`.

### 3. طبقة الـ Presentation
- **`DashboardCubit` / `DashboardState`:** 
  - الـ States أصبحت `immutable` ولا تعتمد على مكتبات خارجية، لتتجنب عملية إعادة البناء غير الضرورية (Redundant Rebuilds).
  - الـ Cubit يتحكم بالتواصل بين הـ UI و الـ Repository باتجاه واحد (Unidirectional Flow)، وفي حال ظهور أخطاء (مثال: انقطاع الإنترنت أثناء حذف تعليق)، لا يقوم بفتح رسائل الخطأ بنفسه، بل يبعث `state.actionMessage` لتتلقاها الـ View.
  - يحمي نفسه من الأخطاء العرضية عند الحذف بعد الخروج من الصفحة `if (isClosed) return;`.
- **`DeveloperDashboardView`:** الشاشة الرئيسية التي تستمع للـ Cubit من خلال `BlocListener` لتقوم بإظهار إشعارات (`AppToast`) بطريقة متسقة ودون كسر تدفق الـ Context.
- **مكونات الواجهة (Widgets):**
  - تم فصل المكونات بناءً على الـ SRP، فكارت العرض `FeedbackAdminCard` لا يعلم شيئاً عن الإجراءات (Actions)، وتم عزل الأزرار في `AdminFeedbackActions`.
  - تحسين الأداء: تم التخلي عن الإنشاء المسبق لكارت المشاركة `FeedbackShareCard`، وأصبح يتم بناءه (Lazily) وتصويره (Screenshot) في الذاكرة فقط عند قيام الأدمن بالضغط على زر "مشاركة".

## 🔒 الأمان والحماية (Security)
باعتبارها صفحة حساسة:
1. **الوصول للمسار:** المسار (`/developer-dashboard`) محمي برمجياً من داخل `GoRouter`.
2. **الـ Redirect Guard:** لا يمكن الدخول للشاشة عبر الروابط المباشرة (Deep-Linking) دون المرور من شاشة `SecretPinDialog`. يتم فحص متغير حالة `SecretPinDialog.isAuthenticated` وفي حال الرفض يتم توجيه المستخدم بالقوة إلى الصفحة الرئيسية (`AppRoutes.home`).

---

## 🚀 ملخص سير العمل للحذف السريع (Optimistic Updates)
عند قيام الأدمن بحذف تعليق معين:
1. يطلب `Cubit` من الـ Repository إخفاء التعليق من الـ Cache المحلي فوراً.
2. يتم عمل `emit` للحالة الجديدة، وتختفي البطاقة مباشرة من عين المستخدم (بدون Loader).
3. خلف الكواليس؛ يبدأ الـ Repository بالتواصل مع Firebase لحذفها.
4. **في حالة النجاح:** لا يحدث أي شيء في الـ UI لأن التعليق مخفي بالفعل.
5. **في حالة الفشل:** يقوم الـ Repository بإرجاع `Failure`، فيقوم الـ Cubit بإعادة استدعاء `getFeedbacks()` لتحديث القائمة الأصلية وإرسال `actionMessage` تُظهر توست خطأ، مع تسجيل الخطأ في الـ `AppLogger`.

## 🧩 التبعيات الرئيسية
- `go_router`: لإدارة توجيه وحماية الصفحة.
- `flutter_bloc`: لإدارة الحالة والتحديثات.
- `screenshot` & `share_plus`: لتحويل التعليقات لصور ومشاركتها مع فريق العمل.
- `collection`: لإجراء عمليات مقارنة عميقة (Deep Equality) للخرائط (Maps) بدون `equatable`.
