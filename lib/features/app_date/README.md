# 📅 مزية التاريخ الهجري والميلادي (app_date)

## نظرة عامة

مزية `app_date` هي المزية المسؤولة عن إدارة التاريخ داخل التطبيق. تعرض للمستخدم **التاريخ الهجري والميلادي** معاً في وقت واحد، وتتيح له ضبط التاريخ الهجري يدوياً إذا كان يختلف مع التقويم المحلي. كذلك تُذكّر المستخدم بالتحقق من التاريخ الهجري في الأشهر الحساسة (رمضان، ذو القعدة، ذو الحجة).

## 📦 طبقة البيانات (Data Layer)

### `app_date_value.dart` — نموذج بيانات التاريخ

هذا الكلاس يُمثّل قيمة التاريخ الموحدة داخل التطبيق، ويحمل التاريخ الميلادي والهجري في نفس الوقت.

| الخاصية | النوع | الوصف |
|---------|------|-------|
| `gregorian` | `DateTime` | التاريخ الميلادي الحالي |
| `hijri` | `HijriCalendar` | التاريخ الهجري المحسوب |
| `adjustment` | `int` | قيمة التعديل بالأيام (+1 أو 0 أو -1) |

**كيف يعمل؟**
- عند إنشاء `AppDateValue`، يأخذ التاريخ الميلادي الحالي (أو تاريخاً محدداً) ويُضيف إليه قيمة التعديل `adjustment`.
- ثم يُحوّل الناتج إلى تاريخ هجري باستخدام مكتبة `hijri`.
- هذا يعني مثلاً: لو `adjustment = 1`، سيُحسب الهجري كأن اليوم هو غداً ميلادياً، مما يرفع التاريخ الهجري يوماً.

```dart
// مثال على الاستخدام
final dateValue = AppDateValue(adjustment: 1);
// dateValue.gregorian = DateTime.now()
// dateValue.hijri     = تاريخ هجري بناءً على غد
// dateValue.adjustment = 1
```

## 🧠 طبقة العرض (Presentation Layer)

### `app_date_cubit.dart` — المتحكم الرئيسي

هو المسؤول عن كل منطق الحالة المتعلق بالتاريخ. يرث من `Cubit<AppDateState>`.

#### ما يفعله عند التهيئة:
1. يقرأ قيمة التعديل المحفوظة من `SharedPreferences` (مفتاح `hijriAdjustment`).
2. ينشئ الحالة الأولية بناءً عليها.
3. يُشغّل مؤقتاً (`Timer`) يُطلق عند منتصف الليل تلقائياً لتحديث التاريخ.

#### الثوابت الداخلية:
```dart
static const _verificationMonths = [
  9,  // رمضان
  11, // ذو القعدة
  12, // ذو الحجة
];
```
الأشهر الهجرية التي يُطلب فيها من المستخدم التحقق من صحة التاريخ.

#### الدوال المتاحة:

| الدالة | الوصف |
|--------|-------|
| `checkMonthlyVerification()` | يتحقق إذا كان الشهر الحالي يتطلب تحقق ولم يُؤكد المستخدم هذا الشهر من قبل |
| `confirmVerification()` | يُسجّل أن المستخدم تحقق من التاريخ في الشهر الحالي ويُغلق الحوار |
| `setAdjustment(int adj)` | يُغيّر قيمة تعديل الهجري ويحفظها في SharedPreferences |
| `resetAdjustment()` | يُعيد التعديل إلى صفر (قيمة التقويم الافتراضية) |
| `refresh()` | يُحدّث التاريخ للوقت الحالي ويُعيد فحص التحقق الشهري |

#### آلية التحديث التلقائي عند منتصف الليل:
```
الوقت الحالي → حساب الفرق حتى منتصف الليل → تشغيل Timer
عند انتهاء Timer → استدعاء refresh() → إعادة جدولة Timer مرة أخرى
```
هذا يضمن أن التاريخ المعروض يتغير دائماً عند منتصف الليل دون الحاجة لإعادة تشغيل التطبيق.

### `hijri_and_gregorian_date_widget.dart` — الويدجت الرئيسي

هذا هو الويدجت الذي يظهر للمستخدم في واجهة التطبيق. يعرض التاريخين ويُدير كل التفاعلات.

**ما يفعله:**
1. عند أول ظهور (`initState`)، يستدعي `checkMonthlyVerification()` بعد بناء الـ UI مباشرة لضمان أن الـ dialog يظهر بعد اكتمال الشاشة.
2. يستمع (`BlocListener`) لتغيير `showVerificationDialog` من `false` إلى `true` ليُظهر حوار التحقق.
3. يعرض التاريخ الهجري كاملاً (يوم/شهر/سنة) + هـ.
4. يعرض التاريخ الميلادي باللغة العربية (اليوم، الاسم، الشهر، السنة، م).
5. عند النقر عليه، يفتح `HijriAdjustmentBottomSheet`.

**مثال على العرض:**
```
6 رمضان 1445 هـ
الخميس ، 6 يناير 2026 م
```

---

### `hijri_adjustment_bottom_sheet.dart` — نافذة ضبط التاريخ

تظهر هذه النافذة عند نقر المستخدم على عرض التاريخ. تُتيح له اختيار تعديل للتاريخ الهجري.

**ما تحتويه:**
- **3 أزرار**: `-1` (يوم قبل)، `0` (بدون تعديل)، `+1` (يوم بعد)
- الزر المحدد حالياً يظهر بخلفية ذهبية مميزة (مع animation سلسة 200ms).
- **زر "العودة للتقويم الطبيعي"**: يظهر بلون مميز إذا كان التعديل ≠ 0، ويعيده للصفر.

**متى يُستخدم؟**
في بعض المناطق، قد يختلف استطلاع الهلال بيوم. هذا الضبط يُتيح للمستخدم مزامنة التاريخ الهجري مع ما يُعلن في بلده.

---

### `hijri_verification_dialog.dart` — حوار التحقق من الشهر

يظهر تلقائياً في بداية الأشهر الهجرية الحساسة (رمضان، ذو القعدة، ذو الحجة).

**ما يعرضه:**
- يُخبر المستخدم بالتاريخ الهجري الحالي كما يراه التطبيق.
- يسأله: "هل هذا صحيح؟"

**الخيارات:**
| الزر | الإجراء |
|------|---------|
| **تأكيد** (نعم صحيح) | يُسجّل الشهر كمؤكد ويُغلق الحوار |
| **إلغاء** (لا، أريد تعديل) | يُسجّل الشهر كمؤكد ثم يفتح `HijriAdjustmentBottomSheet` للضبط |

**ملاحظة مهمة:** يُستخدم `barrierDismissible: false` لمنع إغلاق الحوار بالنقر خارجه، لضمان أن المستخدم يتخذ قراراً واضحاً.

## 🔄 تدفق البيانات (Flow)

```
تشغيل التطبيق
      ↓
AppDateCubit يُهيّئ:
  - قراءة adjustment من SharedPreferences
  - إنشاء AppDateValue بالتعديل المحفوظ
  - جدولة مؤقت منتصف الليل
      ↓
HijriAndGregorianDateWidget يُبنى:
  - initState → checkMonthlyVerification()
  - إذا الشهر حساس ولم يؤكد → showVerificationDialog = true
  - BlocListener يرى التغيير → يُظهر HijriVerificationDialog
      ↓
المستخدم ينقر على التاريخ:
  - يُفتح HijriAdjustmentBottomSheet
  - المستخدم يختار التعديل
  - setAdjustment() → حفظ في SharedPreferences → تحديث الحالة
      ↓
عند منتصف الليل:
  - Timer ينتهي → refresh() → تحديث التاريخ → جدولة مؤقت جديد
```
