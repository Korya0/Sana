```

- اتبع مراحل الـ workflow: تخطيط ← نقد ← تقسيم ← تنفيذ
- التزم بـ very_good_analysis lint rules دائماً

هذا هو context المشروع الكامل:

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

المهمة الجديدة: [وصف مختصر للمهمة]
```

## المراحل الخمس

### 🟦 المرحلة 0 — إعداد السياق (Context Setup)
**الهدف**: أن يفهم الـ AI المشروع قبل أي كلام.

**ما ترسله للـ AI**:
```
أنا أعمل على مشروع سنا (Flutter/Dart).
هذا هو context المشروع:
[محتوي PROJECT_CONTEXT.md]

المهمة الجديدة: [وصف مختصر]
المرحلة الحالية: [0 / 1 / 2 / 3 / 4]
```

---

### 🟨 المرحلة 1 — التخطيط (Planning)
**الهدف**: نخطط سوا قبل ما تكتب أي كود.

**أسئلة لازم تجاوب عليها**:
- [ ] إيه المشكلة أو الميزة الجديدة بالتحديد؟
- [ ] أيٌّ من الـ features الموجودة ستتأثر؟
- [ ] هل هناك بيانات جديدة (API / JSON / Firebase)؟
- [ ] هل هناك State جديد في أي Cubit؟
- [ ] هل تحتاج route جديدة؟
- [ ] هل تحتاج widget مشترك في core؟

**ما يعمله الـ AI**:
- يقترح الـ architecture المناسبة
- يحدد الملفات التي ستتأثر
- يقترح structure الـ code

---

### 🟧 المرحلة 2 — النقد والنقاش (Critique)
**الهدف**: نراجع الخطة سوا ونكتشف المشاكل قبل التنفيذ.

**ما يحدث هنا**:
- أنت تنتقد الخطة وتسأل "ليه مش كذا بدل كذا؟"
- الـ AI يشرح قراراته ويقبل التعديلات المنطقية
- نتفق على النهج النهائي قبل الخطوة التالية

**أسئلة مفيدة للنقد**:
- هل في طريقة أبسط لتحقيق نفس النتيجة؟
- هل هذا يتعارض مع patterns موجودة في المشروع؟
- هل سيؤثر على الـ performance؟
- هل هناك edge cases لم نفكر فيها؟

✅ **لا ننتقل للمرحلة التالية إلا بعد الاتفاق الكامل**

---

### 🟥 المرحلة 3 — تقسيم للخطوات (Task Breakdown)
**الهدف**: تحويل الخطة لخطوات صغيرة وقابلة للتنفيذ والاختبار.

**شكل كل خطوة**:
```
الخطوة N: [اسم واضح]
- الملفات المتأثرة: [list]
- ما سيتغير: [وصف مختصر]
- كيف نتحقق منها: [طريقة الاختبار]
```

**قواعد التقسيم**:
- كل خطوة = وحدة واحدة قابلة للاختبار
- لا خطوة تتضمن أكثر من 2-3 ملفات
- الترتيب مهم: data layer أولاً ثم domain ثم presentation

---

### 🟩 المرحلة 4 — التنفيذ (Execution)
**الهدف**: تنفيذ كل خطوة بشكل مدروس.

كل خطوة تمر بـ **مرحلتين**:

#### 4A — المراجعة (Review)
قبل اعتماد الكود:
- [ ] هل يتبع naming conventions المشروع؟
- [ ] هل يستخدم `AppColors` ولا في hardcoded colors؟
- [ ] هل الـ async صحيح (`unawaited` / `await` / `context.mounted`)?
- [ ] هل الـ Lint مش بيظهر errors؟
- [ ] هل تمت إضافة الـ DI في الملف الصح؟

#### 4B — الاختبار (Test)
- [ ] شغّل التطبيق وتحقق من الخطوة
- [ ] جرّب الـ edge cases المذكورة في المرحلة 3
- [ ] تحقق من الـ Hot Reload / Hot Restart
- [ ] لو في مشاركة صورة — تحقق منها على Android

✅ **بعد اكتمال كل الخطوات: حدّث `PROJECT_CONTEXT.md` لو فيه تغيير في الـ features أو الـ architecture**
